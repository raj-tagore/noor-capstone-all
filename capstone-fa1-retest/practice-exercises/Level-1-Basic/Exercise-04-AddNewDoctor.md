# Exercise 04: AddNewDoctor

## Business Scenario
When a new physician joins CureHospital, the HR department needs to register them in the system before they can be assigned specializations or scheduled for surgeries. The registration process at this stage is simple — only the doctor's name is captured initially, and additional details such as specializations are linked later.

## Problem Statement
Write a repository method named `AddNewDoctor` that accepts a `doctorName` (string) as a parameter and inserts a new Doctor record into the database. The method should create a new `Doctor` object, assign the provided `doctorName` to the `DoctorName` property, add it to the `Doctors` DbSet using `context.Doctors.Add()`, and call `SaveChanges()` to persist the record. The `DoctorID` is auto-generated by the database (IDENTITY column) and should not be set manually. Return `true` if the insertion is successful, or `false` if any exception occurs. Expose this method through a Web API controller action.

## DAL / Repository Method Signature
```csharp
public bool AddNewDoctor(string doctorName)
```

## ASP.NET Web API Controller Requirement
Create an `[HttpPost]` action method named `AddNewDoctor` in `CureHospitalController`. It should accept `doctorName` as a **query parameter** (not from the request body). The controller method should call the repository's `AddNewDoctor` method and return the boolean result wrapped in a `JsonResult`.

## Suggested Controller Method Signature
```csharp
[HttpPost]
public JsonResult AddNewDoctor(string doctorName)
```

## Input Parameters
| Parameter | Type | Description |
|-----------|------|-------------|
| doctorName | string | The name of the new doctor to register (e.g., "James", "Emily") |

## Relevant Database Tables
- **Doctor**: DoctorID (INT, PK, IDENTITY(1001,1)), DoctorName (VARCHAR(50), NOT NULL, UNIQUE)

## Entity Relationships
- `Doctor` is inserted as a standalone entity. No related tables are affected in this exercise.

## Required Operations
1. Create a new `Doctor` entity object.
2. Assign the `doctorName` parameter to the `DoctorName` property of the new object.
3. Add the new Doctor object to the `Doctors` DbSet using `context.Doctors.Add()`.
4. Call `context.SaveChanges()` to persist the new record to the database.
5. Return `true` indicating success.

## Business Rules and Validations
1. The `DoctorID` is auto-generated (IDENTITY) — do **not** set it manually.
2. `DoctorName` has a UNIQUE constraint in the database. If a duplicate name is passed, `SaveChanges()` will throw an exception, which should be caught.
3. No explicit validation of the `doctorName` parameter is required in the repository method beyond what the database constraints enforce.

## Required IF-ELSE Conditions
None. The method follows a straight-through flow: create → add → save → return `true`. The `catch` block handles failures.

## Expected Return Values
| Scenario | Return Value |
|----------|-------------|
| Doctor is successfully added to the database | `true` |
| An exception occurs (e.g., duplicate name, null value) | `false` |

## Exception Handling Requirements
- Wrap the create, add, and save operations inside a `try-catch` block.
- In the `catch` block, return `false`.
- The `catch` should handle a general `Exception`.

- [ ] Controller method `AddNewDoctor` in `CureHospitalController`
